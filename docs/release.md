# 1.0.0-rc.2 源码交付

此版本是 littlechef 改名后的可安装、可审阅的源码候选版。实际环境尚未全部验收，因此不标为生产认证版。

## 包内内容

- Python 后端、原生 JavaScript/CSS/HTML 前端、启动与 Docker 配置。
- 固定直接依赖版本的 `requirements.txt`；传递依赖仍由安装器解析。
- 示例菜谱与插画、README 功能截图、维护文档、回归测试源码。
- `VERSION` 和每个文件的 SHA-256 清单。

不包含运行时 `data/`、真实 `.env`、API 密钥、虚拟环境、下载依赖、Python 字节码、测试缓存、构建输出、日志、Git 历史或 macOS 隐藏资源文件。示例图片和文档截图是项目资源，不是运行缓存。

`run.sh` 与 Docker 应用运行时均禁用 Python 字节码输出；应用数据仍会按设计写入 `data/` 或挂载卷。Docker 构建只发送明确允许的源码路径。

## 验收范围

已在本地使用 Python 3.14 和 Chromium 验证（22 项后端回归及浏览器流程）后端记录/图片回归、照片接口契约（模拟 AI 服务）、设置保存、静态版新建/拍照/刷新/导出、搜索、菜单、下厨计时和底部导航。源码包在独立目录解压后执行检查，压缩包和文件清单进行校验。

以下仍需部署环境验收：

- Docker 构建及 NAS 卷权限；本次环境没有 Docker。
- 实际 AI 密钥、模型可用性、识别准确度与手绘还原度。
- 手机真机相机权限与后台计时行为。
- Python 3.11 容器运行时；代码以 Python 3.11+ 为目标，本次执行环境为 Python 3.14。

PIN 只限制写入，不是读取鉴权；公开部署需要外部访问控制。运行方式、备份和密钥配置见 [README](../README.md) 与 [维护指南](operations.md)。

## 重新打包

```bash
python3 scripts/package_source.py --out /源码目录之外的空输出目录
```

打包采用显式文件类型与目录清单，拒绝源码符号链接和覆盖已有同名版本。相同源码生成相同 ZIP；输出 ZIP、ZIP 校验文件，并在包内附 `SOURCE-MANIFEST.sha256`。

## littlechef 改名与升级

界面、文档、截图、技能名称、导出文件名、Docker 镜像及交付目录统一使用 `littlechef`。原有 `data/` 不迁移、不清空；自定义门牌仍优先于默认品牌。

为避免升级丢失数据，保留以下有意兼容项：浏览器 IndexedDB 名 `kitchen-notes`、PIN 存储键 `kitchen-pin`、HTTP 头 `X-Kitchen-Pin`、旧导出标记 `kitchen_notes`。新导出同时带 `little_chef`。它们是数据/协议兼容标识，不是旧品牌 UI。

旧 `KITCHEN_*` 环境变量仍由 Python 服务接受；新 `LITTLE_CHEF_*` 优先。Compose 为主要运行参数保留旧变量回退。升级 Compose 前先停止旧容器，确认挂载同一个 `data/` 目录，避免两个实例同时写入。

## macOS 工程检查与边界

- `.env` 由 dotenv 解析为数据，不再交给 shell 执行；包含 `$()` 的值不会执行命令。外部环境变量优先于文件，变量插值关闭。
- `run.sh` 支持含空格和中文的路径，验证 Python 3.11+，只在首次运行或依赖清单变化时安装；失败的虚拟环境会明确报错，不会静默删除。
- 持久化 JSON 使用独立临时文件、0600 权限、flush/fsync 后原子替换；替换失败保留旧文件。此保证不等于多文件导入具有数据库事务。
- macOS 常见的不区分大小写文件系统下，已有记录 ID 的大小写冲突会被拒绝，防止覆盖。
- 新记录 ID 带随机后缀；同名并发新建不会互相覆盖。输入结构、日期、数值、库存布尔值及设置在写入前验证。
- 浏览器导入/清空在单个 IndexedDB 事务里提交；坏图片和照片重名冲突会阻止导入并保留原数据。
- Docker、真实 AI、真机相机和 Python 3.11 运行时仍须部署环境验收。本版在 macOS 的 Python 3.14 与 Chromium 测试，不能宣称所有环境绝对零缺陷。
